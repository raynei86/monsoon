# Developer guide

This guide gives a high-level overview of the internal architecture and
algorithms used by Monsoon.

## Codebase layout

- `src/types.lisp` — core types, square and piece helpers, and bitboard
  constants.
- `src/position.lisp` — `position` struct and helpers for board state updates.
- `src/utils.lisp` — bitboard helpers and the iterate clause used by move
  generation.
- `src/moves.lisp` — move representation and move generation logic.
- `src/fen.lisp` — FEN parsing and `position-from-fen`.

## Core representation

Monsoon uses a bitboard-based representation. A `position` holds:

- 12 colored-piece bitboards (`pos-boards`): one per piece kind and color.
- 2 color bitboards (`pos-by-color`): aggregate by color.
- 6 piece bitboards (`pos-by-piece`): aggregate by piece kind.
- An occupancy bitboard that is always kept in sync.
- Side to move, castling rights, en passant square, and clocks.

State updates are done through `place-piece!` and `remove-piece!` so all
tracking bitboards stay consistent. `do-move` creates a copy of the
position, updates boards, and applies rule-specific effects (captures,
promotion, castling, en passant, clocks).

## Move generation overview

Move generation produces *pseudo-legal* moves and then filters with
`legal-move-p` using `king-in-check-p`.

### Precomputed attack tables

- King and knight moves are precomputed for every square into bitboard tables.
- Sliding piece attacks use precomputed ray tables for each direction.
  `ray-attacks+` and `ray-attacks-` cut rays at the first blocker to
  produce rook/bishop/queen attacks.

### Pawns

Pawn move generation derives pushes and captures from shift operations.
Promotion and en passant moves are emitted by splitting target bitboards by
promotion rank and by masking the en passant square.

### Castling

Castling is generated by checking castling rights plus empty path masks. The
king move is emitted, and `do-move` relocates the rook based on flags.

## Check detection

`king-in-check-p` computes attacks against the king square by:

- Using pawn attack shifts from the king’s perspective.
- Using the knight and king attack tables.
- Using ray attacks for bishop/rook/queen sliders.

This avoids generating all opponent moves and keeps check detection local.
